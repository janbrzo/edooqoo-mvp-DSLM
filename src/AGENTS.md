# AGENTS.md (scoped rules)

One rule per entry with a one-line why. Moved from the root AGENTS.md.

## Student Workspace

- Student Workspace tab and Learning plan segment state live only in the URL and are resolved via `src/lib/students/workspaceTabs.ts` (`resolveModelSegment` for `view=`); legacy `?tab=` and `view=` values are permanent — because sent emails and bookmarks carry them.
- The next lesson shown anywhere (Prep card, Learning plan Up next, worksheet form Next steps banner) is ordered only by `orderUpNext` in `src/lib/dslm/learningPlan.ts` — because suggestion `sequence_number` restarts per phase and two selectors once proposed different lessons.

## Runtime Safety

- The anonymous landing hero hands its topic to the mounted form only through `worksheet:heroTopicPrefill` and `src/lib/worksheet/heroTopicPrefill.ts`; the listener updates `lessonTopic` only and never sets auto-generation flags, submits or consumes tokens, because the hero CTA must preserve teacher review and the existing anonymous generation contract.
- The public `/welcome-test/demo` route reuses the real adaptive questions but keeps answers in an allowlisted 7-day localStorage session and recordings in local IndexedDB; its deterministic result uses the shared bank-2 ladder and traits, never AI grading or student-test RPCs, and its expiring hash link contains only the bounded summary, because public previews must never create learner evidence, upload recordings or expose open answers. Teacher Film remains an explicit-play, scripts-only sandboxed embed with no parent bridge or network access.
- Public placement reports are stored, emailed and claimed only through the service-only `public-placement-report` Edge Function (`public_placement_reports`, 7-day expiry, bounded summary only, emails never returned to the browser; separate teacher `report_token` and `student_report_token`, the audience is decided by the token on the server and claim accepts only the teacher token; invited results are sent automatically, and a student token may forward its report to a teacher at most 3 times); anonymous Quick Send invites (`public_placement_invites`, 7 days) route the result to the inviting teacher server-side without exposing their email, and a claim creates exactly one student plus learning profile for the signed-in teacher and is reserved atomically, because an anonymous result must never reach another teacher or create duplicate learners.
- Generation conversion slides own presentation-only rotation and use explicit modal audience/learner props plus the canonical `studentTabPath` for new-tab actions; never fetch learner evidence or modify generation-job lifecycle, because waiting-time promotion must not interrupt worksheets or expose private learning records.

- Public Gallery recommendations use only reviewed source links revalidated through the publication-filtered metadata RPC, fetched without a teacher session; never embed worksheet bodies in SEO snapshots or infer learner mastery from worksheet levels, because publication is revocable and private learning evidence is not promotional content.

- Homework and shared worksheet answers are autosaved only through `createPendingSaves` in `src/lib/answers/pendingSaves.ts` (one debounce timer per exercise, `flush()` on submit and unmount), never a single shared timer; a homework save sends only the keys this tab changed (`buildHomeworkDelta` in `src/lib/homework/deltaSave.ts`), a blur without edits writes nothing and the teacher's "View as student" is `readOnly`; on `pagehide` / `beforeunload` the changed keys of every pending exercise go out once as a keepalive request (`buildKeepaliveSaveRequest`, `src/lib/homework/keepaliveSave.ts`) and every saved answer passes `sanitizeAnswerValue` (no NUL, 20 000 characters) — because the last 1.5 s of typing was lost on close or reload, a NUL character made an exercise unsavable forever behind a "connection" message, and a shared timer dropped the pending save of one exercise whenever another was edited within 1.5 s, and whole-exercise snapshots from a stale tab or a bare blur overwrote the student's newer answers.
- Student-facing pages never infer "unassigned" or "not shared" from an anonymous read of `worksheets` (RLS hides the row, so null means unknown, see `isKnownUnassigned` in `src/lib/worksheet/shareAssignment.ts`); access is decided by `verify_worksheet_student_email` — because that inference blocked every anonymous student on shared worksheet links.
- The default homework deadline comes from `suggestDeadlineFromLessons` (`src/lib/homework/lessonDeadline.ts`: 2 h before the student's next booked lesson in the calendar time zone, at least 4 h of work time, within 14 days, else the usual +6 days) and a deadline the teacher touched is never replaced; the Student tab builds the homework modal from the worksheet the teacher picked, never from the latest one by default alone — because the deadline fell after the lesson where the homework should be discussed and the picker did not exist.
- Client logging goes through `src/utils/logger.ts`, never raw `console.*` — because production logs must not leak student data.
- Supabase hooks return early when demo mode (`edooqoo_demo_mode`) is active; `src/lib/demo/demoFetchGuard.ts` (installed by `src/lib/demo/installDemoFetchGuard.ts`, the first import of `main.tsx`) answers any remaining REST read carrying a `demo-` id with an empty result — because demo IDs are not UUIDs and crash queries.
- Teacher-only pages call `useTeacherAuthRedirect` instead of ad-hoc `navigate('/')` — because email deep links must survive login via `state.from`.

- Student Hub goals are exposed only by `get-student-hub-data` (live, same-teacher goals; unaccepted `welcome_test_auto` hidden) and shaped only by the pure `src/lib/studentHub/hubGoals.ts`, which never infers progress beyond the teacher's saved value — because learners must see only confirmed goals and no invented mastery.
- Student Hub homework rows share the canonical `homeworkState` projection in `studentHub/homeworkLifecycle.ts`; native feedback reads only the published share-token/email review for a homework in the current successful Hub response, with request-scoped cancellation and no redo or grading writes, because teacher closure is not submission and stale learner responses must never expose another review.

- Goal progress suggestions come only from the pure `auditGoal` in `src/lib/dslm/goalEvidenceAuditor.ts` (caller-supplied time, single read-time forgetting, flashcards/excluded keys skipped, category words never match) and are shown teacher-only via `useGoalEvidenceAudit`; they are written to `manual_progress_pct`/`is_achieved` only on an explicit teacher click, because the Student Hub must show confirmed progress and one exercise must not inflate a goal.
- Goal deadline trajectory is classified only by the pure `computeGoalVelocity` (`src/lib/dslm/deadlineVelocity.ts`) and shown teacher-only via `GoalVelocityHint`; it never writes data, and hard deadlines (exam, interview, presentation) are never proposed for extension, only scope narrowing - because a moved exam date misrepresents reality and automatic date changes would confuse learners.

Rules for `supabase/` (Edge Functions, SQL, access control) live in `supabase/AGENTS.md` and the nested `AGENTS.md` files under it.
