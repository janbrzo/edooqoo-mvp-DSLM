# AGENTS.md (scoped rules)

One rule per entry with a one-line why. Moved from `supabase/AGENTS.md`.

## Shared evaluation helpers

- Skill mastery shown or sent to a model is `effectiveMastery` / `withEffectiveMastery` from `supabase/functions/_shared/forgetting.ts` (14 days grace, 60 day half-life, floor 50%), applied at read time from `last_event_at`; `student_skill_metrics.current_mastery` stays the stored audit value and is never overwritten with it; planning prompts show weak skills only through `buildWeakAreasBlock` and the learner only through `buildStudentProfileBlock` in `_shared/dslmPromptCore.ts` (skills grouped by `canonicalSkill` in `_shared/skillLabels.ts`, flashcards excluded, age = now - `last_event_at`, never `updated_at`, no fresh evidence stated explicitly, real `students` / `student_learning_profiles` columns only, student text via `promptSafety`) - because the stored average is time-normalised, so a single old event kept its score forever and nothing was ever forgotten, and the prompts listed eight identical lines and fields that do not exist.
- AI quality scores become item mastery only through `scoreToMastery` (0 stays 0, a missing score is -1 / unevaluated) and exercise mastery only through `averageScoredMastery` in `supabase/functions/_shared/itemMastery.ts` — because `quality_score || 0.7` stored non-answers as 70 and -1 placeholders dragged homework averages down.
- Closed exercise key verdict is computed once by `calculateItemMastery` in `supabase/functions/_shared/itemMastery.ts` and exposed as `key_verdict` by `_shared/closedItemContext.ts`; AI never lowers a key-correct score or reveals answers and may only raise a typed (non-selection) item the key marks wrong or review through `aiAlternativeMastery` (score >= 0.85 -> 85-95, `source: 'ai_alternative'`); only `shouldSendClosedItemToAi` / `selectClosedItemsForAi` (`_shared/closedEvaluation.ts`) decide which closed items reach the model: typed items the key marks wrong or review (never selection items, key-correct items or a single-letter pick), all items only on a teacher Mark done; a row with nothing to send is still written without a model call so events and mastery stay identical; explanations are displayed only through `ClosedAiExplanations` - because model errors must never contradict the key or DSLM, valid alternatives must not be scored 0, and items the model cannot change cost 79% of the closed calls.
- Open and closed exercise types come only from `OPEN_EXERCISE_TYPES` / `CLOSED_EXERCISE_TYPES` in `supabase/functions/_shared/itemMastery.ts` (enforced by `src/lib/answers/__tests__/exerciseTypeLists.test.ts`), and the level sent to evaluation models only from `resolveEnglishLevel` (`_shared/englishLevel.ts`) — because four drifted lists sent different types to AI per entry point and every learner was graded as 'Intermediate'.
- Welcome Test traits are reconstructed only by `reconstructTraits` and stored answers are keyed only by `WELCOME_TEST_QUESTION_IDS` (`supabase/functions/_shared/welcomeTestTraits.ts`, parity-tested against `src/data/welcomeTestQuestions.ts`); the Learning Path Score is computed only by `computeLearningPathScore` (v2: missing signal = null, never 50; capacity cap) and declared-vs-measured pairs only by `computeDivergences` in code, never by the model; a stored answer is matched to an option only by `matchOptionIndex` and any edit of an option's text adds a `LEGACY_OPTION_TEXT` entry (`_shared/welcomeTestOptionAliases.ts`); the CEFR level is computed only by `estimateLevel` (`_shared/welcomeTestLevel.ts`, after AI scores; a force re-run keeps a level stored by an older `LEVEL_ALGORITHM_VERSION`); answer events are built only by `_shared/welcomeTestEventPayload.ts` (client and `reconcile_welcome_test_events`) and a completed retake marks older attempts' events `superseded_at` (kept for history, never deleted); process-welcome-test is the only grader: it rebuilds answers from `student_test_questions`, re-grades keyed rows with `regradeQuestionRows` (`_shared/welcomeTestKeyedAnswer.ts`, the browser verdict is provisional) and runs `calculate_test_results` (scores over scored items only), `get_test_questions_by_share_token` never returns `correct_answer`; the level needs the v3 evidence gate (`MIN_SCORED_ITEMS`, `MIN_ANSWERED_ITEMS`, `MIN_SCORED_SKILLS`, else null and `raw_answers.level_evidence.status = 'insufficient'`); traits carry `INTERPRETATION_VERSION` and `trait_evidence` (`_shared/welcomeTestInterpretation.ts`), a mapping change bumps the version; AI per-question scores are accepted only by `acceptAiScores` (ids sent this run, clamped 0-100, injection-capped, `_shared/welcomeTestScoring.ts`) — because the em-dash copy edit silently broke trait reconstruction of stored profiles, the model returned scores for ids it copied from the prompt example, and the force re-run keyed answers as `wt_q{index+1}` and corrupted profiles, fallbacks looked like measurements and the AI could not triangulate what it never received.
- Pacing style (Scientific/Pragmatic) is computed only by `computeStylePacing` and intensity only by `computeIntensity` in `supabase/functions/_shared/pacing.ts`, from real profile columns, with inputs loaded only by `computeStylePacingForStudent`; deadline floors apply last and intensity never changes the style number; prompt-time pacing (`resolvePromptPacing`) uses the stored value whenever `last_pacing_set_manually` is set (true or false), never by comparing it with 50, and for a never-set student (flag NULL, the column default since `20261021090000`; new students are inserted with the column default `DEFAULT_PACING_MODE` = 50) takes the `computeStylePacing` result, with `autoPacingIndex` only as the fallback when its inputs cannot be read; a pending pacing proposal expires after `PACING_PROPOSAL_MAX_AGE_DAYS` (14) and accepting one recomputes the value through `recalculate-pacing` in apply mode, never the stored old number — because three pacing algorithms disagreed, automatic pacing was dead (the default `false` looked like "set") and a stale proposal overwrote a newer situation.
