# AGENTS.md (scoped rules)

One rule per entry with a one-line why. Moved from the root AGENTS.md.

## Answers & Evaluation

- New event ratings are normalized by `normalize_dslm_ratings` at the `student_events` boundary; knowledge classification updates the original observation and flashcards also emit word-level ratings, without changing card scoring or historical events, because every evidence source must reach metrics without invented scores or duplicate observations.

- All worksheet text answer checking goes through `src/lib/answers/matchAnswer.ts`; an uncertain match returns `review`, never `wrong` (sole exception: Welcome Test grammar fill_blank items are compared strictly in `src/lib/welcomeTest/keyedAnswer.ts`, because the word form is what they test) — because false negatives destroy learner trust and DSLM accuracy.
- "Homework waiting for review" is decided only by `isHomeworkAwaitingReview` in `src/lib/homework/reviewState.ts`, and every review entry point links to `/homework/:id/review` — because the dashboard, timeline and homework list used to disagree and the review page was unreachable after the first review.

- Every DSLM pipeline SQL function and trigger (answer -> event triggers, metric engine, answer RPCs, AI queue RPCs) is defined in `supabase/migrations/`, never only in the dashboard (enforced by `src/lib/__tests__/dslmSqlBaseline.test.ts`) — because the engine existed only in production and could not be reviewed.
- Answer -> event triggers delete and re-insert only events of their own `event_source` (homework/worksheet) and skip writes that change none of answers, item_evaluations, audio_answers, mastery, eval_trigger, exercise_type; skill metrics recompute on INSERT, UPDATE and DELETE of `student_events`, Mark done is saved/undone only via `save_mark_done_evaluation` / `delete_mark_done_evaluation`, is prefilled only by `calculateInitialMasteryForItem` (shared key verdict, 0-100) and supersedes the student's worksheet ratings of the whole exercise in `compute_skill_metric` (v3, `20261015090000`: one data point per event and skill, advisory lock per metric, `insufficient_data` below 4 points, ascending history with timestamps, a reopened Mark done prefills the saved teacher ratings); a changed worksheet answer clears its `ai_evaluation` and an unchanged re-save keeps `ai_alternative` raises — because teacher evaluations were wiped by later student saves, metrics drifted from events and RLS silently dropped direct teacher updates, a teacher correction was averaged with the verdict it corrected, a 10-item exercise counted ten times, and stale AI scores survived edits.
- Skill mastery shown or sent to a model is `effectiveMastery` / `withEffectiveMastery` from `supabase/functions/_shared/forgetting.ts` (14 days grace, 60 day half-life, floor 50%), applied at read time from `last_event_at`; `student_skill_metrics.current_mastery` stays the stored audit value and is never overwritten with it - because the stored average is time-normalised, so a single old event kept its score forever and nothing was ever forgotten.
- The AI evaluation queue is drained only through `claim_pending_ai_evaluations` (atomic, one row per worker step, stale-lock recovery, max 3 attempts including dead runs) and evaluates the answers stored in `worksheet_student_answers` at processing time; a scheduled call with `x-cron-secret` queues each saved answer at most once per save via `list_worksheet_answers_needing_ai_evaluation`, and retries stay with the claim; submitted homework answers whose tab-side AI never finished are evaluated by the same scheduled run through `list_homework_answers_needing_ai_evaluation` / `claim_homework_answer_ai_attempt` (max 3 attempts, never overwriting a finished row) — because double processing, rows stuck in 'processing', no retries and evaluation that depended on an open browser tab lost or duplicated evaluations.
- `verify-open-answers` maps model results to answers by the echoed item id (`verify-open-answers/evaluationMapping.ts`); a missing, unparseable or non-numeric score leaves an open item unevaluated (never a made-up 0.7, never 25 in the Welcome Test); scores are read only by `parseModelScore` and a forced 0 for "no answer" only by `isNonAnswerText` (whole short answer) in `verify-open-answers/answerSignals.ts` — because positional mapping and fallback scores wrote fabricated values into DSLM, `parseFloat` turned an 85 into full marks and an unanchored "I don't know" pattern zeroed real answers.
- AI quality scores become item mastery only through `scoreToMastery` (0 stays 0, a missing score is -1 / unevaluated) and exercise mastery only through `averageScoredMastery` in `supabase/functions/_shared/itemMastery.ts` — because `quality_score || 0.7` stored non-answers as 70 and -1 placeholders dragged homework averages down.
- Closed exercise key verdict is computed once by `calculateItemMastery` in `supabase/functions/_shared/itemMastery.ts` and exposed as `key_verdict` by `_shared/closedItemContext.ts`; AI never lowers a key-correct score or reveals answers and may only raise a typed (non-selection) item the key marks wrong or review through `aiAlternativeMastery` (score >= 0.85 -> 85-95, `source: 'ai_alternative'`); explanations are displayed only through `ClosedAiExplanations` - because model errors must never contradict the key or DSLM, while valid alternatives must not be scored 0.
- Open and closed exercise types come only from `OPEN_EXERCISE_TYPES` / `CLOSED_EXERCISE_TYPES` in `supabase/functions/_shared/itemMastery.ts` (enforced by `src/lib/answers/__tests__/exerciseTypeLists.test.ts`), and the level sent to evaluation models only from `resolveEnglishLevel` (`_shared/englishLevel.ts`) — because four drifted lists sent different types to AI per entry point and every learner was graded as 'Intermediate'.
- Welcome Test traits are reconstructed only by `reconstructTraits` and stored answers are keyed only by `WELCOME_TEST_QUESTION_IDS` (`supabase/functions/_shared/welcomeTestTraits.ts`, parity-tested against `src/data/welcomeTestQuestions.ts`); the Learning Path Score is computed only by `computeLearningPathScore` (v2: missing signal = null, never 50; capacity cap) and declared-vs-measured pairs only by `computeDivergences` in code, never by the model; a stored answer is matched to an option only by `matchOptionIndex` and any edit of an option's text adds a `LEGACY_OPTION_TEXT` entry (`_shared/welcomeTestOptionAliases.ts`); the CEFR level is computed only by `estimateLevel` (`_shared/welcomeTestLevel.ts`, after AI scores; a force re-run keeps a level stored by an older `LEVEL_ALGORITHM_VERSION`); answer events are built only by `_shared/welcomeTestEventPayload.ts` (client and `reconcile_welcome_test_events`) and a completed retake supersedes older attempts' events; AI per-question scores are accepted only by `acceptAiScores` (ids sent this run, clamped 0-100, injection-capped, `_shared/welcomeTestScoring.ts`) — because the em-dash copy edit silently broke trait reconstruction of stored profiles, the model returned scores for ids it copied from the prompt example, and the force re-run keyed answers as `wt_q{index+1}` and corrupted profiles, fallbacks looked like measurements and the AI could not triangulate what it never received.
- Pacing style (Scientific/Pragmatic) is computed only by `computeStylePacing` and intensity only by `computeIntensity` in `supabase/functions/_shared/pacing.ts`, from real profile columns; deadline floors apply last and intensity never changes the style number; prompt-time pacing (`resolvePromptPacing`) uses the stored value whenever `last_pacing_set_manually` is set (true or false), never by comparing it with 50 — because three pacing algorithms disagreed and no Welcome Test signal reached pacing (the profile select named non-existent columns).
