## Answers & Evaluation

- Internal configuration, newsletter and DSLM audit tables retain service-only policies and explicit service grants; `consume_newsletter_rate_limit` is service-only and client RPC grants are changed only through an exact audited allowlist, because blanket definer revocation breaks authorized teacher and share-token workflows.

- New event ratings are normalized by `normalize_dslm_ratings` at the `student_events` boundary; knowledge classification updates the original observation and flashcards also emit word-level ratings, without changing card scoring or historical events, because every evidence source must reach metrics without invented scores or duplicate observations.

- All worksheet text answer checking goes through `src/lib/answers/matchAnswer.ts`; an uncertain match (one that cannot be proven wrong) returns `review`, never `wrong`, and only these cases are provably wrong: an error-correction answer that copies the source sentence (unless the key says no error), and in grammar items (`grammar: true`: gap-text, fill-in-blanks, complete-word) a difference that is only a regular ending (s, es, ed, d, ing, ly, er, est, ies) on a stem of 3+ letters whose ending does not repeat the last stem letter; typos, transpositions, word order and vocabulary items stay `review` (Welcome Test grammar fill_blank items are compared strictly in `supabase/functions/_shared/welcomeTestKeyedAnswer.ts`, because the word form is what they test) — because false negatives destroy learner trust and DSLM accuracy, while unscorable inert items stop giving the negative signal they exist to measure.
- "Homework waiting for review" is decided only by `isHomeworkAwaitingReview` in `src/lib/homework/reviewState.ts`, and every review entry point links to `/homework/:id/review` (the notification bells through `notificationPath` in `src/lib/notifications/notificationRoute.ts`, never to the student share link) — because the dashboard, timeline and homework list used to disagree and the review page was unreachable after the first review; a homework is open only while `completed_at` is NULL (enforced in SQL by `save_homework_answer`, `submit_homework_answers` with the `homework_closed` error, an idempotent `mark_homework_completed_internal` that never overwrites a student return, and the owner-only `reopen_homework`), and its lifecycle (open, submitted, reviewed, closed) is read only by `homeworkState` — because Mark done used to leave the homework writable and a late submit never reached the review queue.

- A homework's exercise snapshot (answer keys included) leaves the database only through `get_homework_exercises_by_share_token` (owner teacher, or share token + assigned email) and the link-only `get_homework_by_share_token` returns exercises, image and audio just to the owner (`20261028100000`, `20261028100100`; the student page reads them in `HomeworkPage` after `verifyStudentEmail`) — because a bare link used to carry every answer key and the page only blurred it.
- A closed homework item the key leaves unrated ("review") is decided only by the owner teacher through `set_homework_item_verdict` (`20261028110000`, now a wrapper of `set_homework_item_score`, `20261028140000`: ratings of that question become 100 or 0 with `source: 'teacher'`, 0-100 for open answers listed by `findItemsToScore`; exercise mastery = share of rated questions at 50 or more for closed, the mean for open; only a row the server finished grading can be rated), listed by `findItemsToCheck` (`src/lib/homework/reviewItems.ts`) on `/homework/:id/review`, never by the browser or the AI — because unrated items never reached the DSLM and word-order exercises showed an inflated mastery.
- What the student sees after "Send review" (the teacher's per-exercise comments and decisions on unrated items) is read only through `get_homework_review_by_share_token` (share token + assigned email, null until `reviewed_at`; `20261028120000`) and shown by `HomeworkPage`, and the teacher toast may promise only that — because the review used to claim a delivery that had no student-facing read.
- Every DSLM pipeline SQL function and trigger (answer -> event triggers, metric engine, answer RPCs, AI queue RPCs) is defined in `supabase/migrations/`, never only in the dashboard (enforced by `src/lib/__tests__/dslmSqlBaseline.test.ts`) — because the engine existed only in production and could not be reviewed.
- Answer -> event triggers delete and re-insert only events of their own `event_source` (homework/worksheet) and skip writes that change none of answers, item_evaluations, audio_answers, mastery, eval_trigger, exercise_type; skill metrics recompute on INSERT, UPDATE and DELETE of `student_events`, Mark done is saved/undone only via `save_mark_done_evaluation` / `delete_mark_done_evaluation`, is prefilled only by `calculateInitialMasteryForItem` (shared key verdict, 0-100) and supersedes the student's worksheet ratings of the whole exercise in `compute_skill_metric` (v3, `20261015090000`, plus `20261017100000`: one data point per event and skill, events with `superseded_at` ignored, advisory lock per metric, `insufficient_data` below 4 points and allowed by `student_skill_metrics_trend_check`, ascending history with timestamps, a reopened Mark done prefills the saved teacher ratings); a changed worksheet answer clears its `ai_evaluation` and an unchanged re-save keeps `ai_alternative` raises — because teacher evaluations were wiped by later student saves, metrics drifted from events and RLS silently dropped direct teacher updates, a teacher correction was averaged with the verdict it corrected, a 10-item exercise counted ten times, and stale AI scores survived edits.
- A DSLM event's weight in `compute_skill_metric` comes only from `public.dslm_event_weight` (version 1: homework submitted 1.0, homework draft 0.8, other sources 1.0; `docs/ux/learning-model-spec.md` §14), and `submit_homework_answers` flips `event_payload.is_submitted` of the submitted exercises — because the answer trigger ignores a submit-only change, so the draft flag stayed false for exercises the AI never re-evaluated.
- Skill mastery shown or sent to a model is `effectiveMastery` / `withEffectiveMastery` from `supabase/functions/_shared/forgetting.ts` (14 days grace, 60 day half-life, floor 50%), applied at read time from `last_event_at`; `student_skill_metrics.current_mastery` stays the stored audit value and is never overwritten with it; planning prompts show weak skills only through `buildWeakAreasBlock` and the learner only through `buildStudentProfileBlock` in `_shared/dslmPromptCore.ts` (skills grouped by `canonicalSkill` in `_shared/skillLabels.ts`, flashcards excluded, age = now - `last_event_at`, never `updated_at`, no fresh evidence stated explicitly, real `students` / `student_learning_profiles` columns only, student text via `promptSafety`) - because the stored average is time-normalised, so a single old event kept its score forever and nothing was ever forgotten, and the prompts listed eight identical lines and fields that do not exist.
- The AI evaluation queue is drained only through `claim_pending_ai_evaluations` (atomic, one row per worker step, stale-lock recovery, max 3 attempts including dead runs) and evaluates the answers stored in `worksheet_student_answers` at processing time; a scheduled call with `x-cron-secret` queues each saved answer at most once per save via `list_worksheet_answers_needing_ai_evaluation`, and retries stay with the claim; submitted homework answers are evaluated by the server right after submit (`processSubmittedHomework`, homework_id + share token) and, when that did not finish, by the same scheduled run through `list_homework_answers_needing_ai_evaluation` / `claim_homework_answer_ai_attempt` (max 3 attempts, never overwriting a finished row); `save_homework_answer` validates student ratings against the exercise's own skills, merges saves by key and takes the exercise type from the homework snapshot, and the ratings of submitted closed exercises are rebuilt by the server from the answers with `buildClosedItemEvaluations` (`_shared/closedRatings.ts`, parity-tested against the client builder; selection types are finalised in `finalizeClosedRows`, `eval_trigger` 'submit_homework' marks them done, and unsubmitted closed drafts are re-rated from the key by the scheduled run, marked '10min_inactivity') — because the ratings a browser sent for selection exercises were never checked and went straight into skill metrics, double processing, rows stuck in 'processing', no retries and evaluation that depended on an open browser tab lost or duplicated evaluations.
- `verify-open-answers` maps model results to answers by the echoed item id (`verify-open-answers/evaluationMapping.ts`); a missing, unparseable or non-numeric score leaves an open item unevaluated (never a made-up 0.7, never 25 in the Welcome Test); scores are read only by `parseModelScore` and a forced 0 for "no answer" only by `isNonAnswerText` (whole short answer) in `verify-open-answers/answerSignals.ts` — because positional mapping and fallback scores wrote fabricated values into DSLM, `parseFloat` turned an 85 into full marks and an unanchored "I don't know" pattern zeroed real answers.
- AI quality scores become item mastery only through `scoreToMastery` (0 stays 0, a missing score is -1 / unevaluated) and exercise mastery only through `averageScoredMastery` in `supabase/functions/_shared/itemMastery.ts` — because `quality_score || 0.7` stored non-answers as 70 and -1 placeholders dragged homework averages down.
- Closed exercise key verdict is computed once by `calculateItemMastery` in `supabase/functions/_shared/itemMastery.ts` and exposed as `key_verdict` by `_shared/closedItemContext.ts`; AI never lowers a key-correct score or reveals answers and may only raise a typed (non-selection) item the key marks wrong or review through `aiAlternativeMastery` (score >= 0.85 -> 85-95, `source: 'ai_alternative'`); only `shouldSendClosedItemToAi` / `selectClosedItemsForAi` (`_shared/closedEvaluation.ts`) decide which closed items reach the model: typed items the key marks wrong or review (never selection items, key-correct items or a single-letter pick), all items only on a teacher Mark done; a row with nothing to send is still written without a model call so events and mastery stay identical; explanations are displayed only through `ClosedAiExplanations` - because model errors must never contradict the key or DSLM, valid alternatives must not be scored 0, and items the model cannot change cost 79% of the closed calls.
- Open and closed exercise types come only from `OPEN_EXERCISE_TYPES` / `CLOSED_EXERCISE_TYPES` in `supabase/functions/_shared/itemMastery.ts` (enforced by `src/lib/answers/__tests__/exerciseTypeLists.test.ts`), and the level sent to evaluation models only from `resolveEnglishLevel` (`_shared/englishLevel.ts`) — because four drifted lists sent different types to AI per entry point and every learner was graded as 'Intermediate'.
- Welcome Test traits are reconstructed only by `reconstructTraits` and stored answers are keyed only by `WELCOME_TEST_QUESTION_IDS` (`supabase/functions/_shared/welcomeTestTraits.ts`, parity-tested against `src/data/welcomeTestQuestions.ts`); the Learning Path Score is computed only by `computeLearningPathScore` (v2: missing signal = null, never 50; capacity cap) and declared-vs-measured pairs only by `computeDivergences` in code, never by the model; a stored answer is matched to an option only by `matchOptionIndex` and any edit of an option's text adds a `LEGACY_OPTION_TEXT` entry (`_shared/welcomeTestOptionAliases.ts`); the CEFR level is computed only by `estimateLevel` (`_shared/welcomeTestLevel.ts`, after AI scores; a force re-run keeps a level stored by an older `LEVEL_ALGORITHM_VERSION`); answer events are built only by `_shared/welcomeTestEventPayload.ts` (client and `reconcile_welcome_test_events`) and a completed retake marks older attempts' events `superseded_at` (kept for history, never deleted); process-welcome-test is the only grader: it rebuilds answers from `student_test_questions`, re-grades keyed rows with `regradeQuestionRows` (`_shared/welcomeTestKeyedAnswer.ts`, the browser verdict is provisional) and runs `calculate_test_results` (scores over scored items only), `get_test_questions_by_share_token` never returns `correct_answer`; the level needs the v3 evidence gate (`MIN_SCORED_ITEMS`, `MIN_ANSWERED_ITEMS`, `MIN_SCORED_SKILLS`, else null and `raw_answers.level_evidence.status = 'insufficient'`); traits carry `INTERPRETATION_VERSION` and `trait_evidence` (`_shared/welcomeTestInterpretation.ts`), a mapping change bumps the version; AI per-question scores are accepted only by `acceptAiScores` (ids sent this run, clamped 0-100, injection-capped, `_shared/welcomeTestScoring.ts`) — because the em-dash copy edit silently broke trait reconstruction of stored profiles, the model returned scores for ids it copied from the prompt example, and the force re-run keyed answers as `wt_q{index+1}` and corrupted profiles, fallbacks looked like measurements and the AI could not triangulate what it never received.
- Pacing style (Scientific/Pragmatic) is computed only by `computeStylePacing` and intensity only by `computeIntensity` in `supabase/functions/_shared/pacing.ts`, from real profile columns, with inputs loaded only by `computeStylePacingForStudent`; deadline floors apply last and intensity never changes the style number; prompt-time pacing (`resolvePromptPacing`) uses the stored value whenever `last_pacing_set_manually` is set (true or false), never by comparing it with 50, and for a never-set student (flag NULL, the column default since `20261021090000`; new students are inserted with the column default `DEFAULT_PACING_MODE` = 50) takes the `computeStylePacing` result, with `autoPacingIndex` only as the fallback when its inputs cannot be read; a pending pacing proposal expires after `PACING_PROPOSAL_MAX_AGE_DAYS` (14) and accepting one recomputes the value through `recalculate-pacing` in apply mode, never the stored old number — because three pacing algorithms disagreed, automatic pacing was dead (the default `false` looked like "set") and a stale proposal overwrote a newer situation.
- A DSLM migration is applied to production together with the code that calls it, and `pg_proc` / `pg_constraint` are checked afterwards; production SQL changes avoid `DROP` (use `CREATE OR REPLACE`, including triggers) because the SQL tool waits for a manual confirmation and times out; a function whose new argument would leave two overloads (PostgREST cannot choose) is replaced in its own migration file run in the SQL Editor (`save_mark_done_evaluation` and optional `p_prior_verdict`, `20261027090200`, order in `docs/operational/iteration-10-rollout.md`), the validation loop (`dslm_interpretation_params` version 1 seeded from code and parity-tested in `dslmParamsParity.test.ts`, `dslm_decision_log` written only through `log_dslm_decision`, `param_version` columns) is additive and never read by `compute_skill_metric` - because 20261015090300-090500 stayed unapplied while the deployed function called them, and compute_skill_metric v3 shipped without the constraint it needed, rolling back every new rated event.
- Welcome Test banks (`WELCOME_TEST_BANK_SIZES` in `_shared/welcomeTestBank.ts`) only grow by appending questions to `ALL_WELCOME_TEST_QUESTIONS`; display order and which adaptive questions a student sees come from `_shared/welcomeTestFlow.ts` (`visibleBranchIds`, `shownRows` on the server, `sectionsFor` in the browser), a bank 2 level comes only from `estimateLevelLadder` over `LEVEL_ITEM_CEFR` (bank 1 stays on `estimateLevel`), and `CURRENT_WELCOME_BANK` in `src/lib/welcomeTest/seed.ts` is raised to 2 only after the listening recordings exist — because a stored `question_index` must keep its meaning, a question never shown must not count as skipped or missed, and a transcript shown instead of audio would measure reading, not listening.
- `public.worksheets.prompt` and `ip_address` are not readable by anon/authenticated (table-level SELECT revoked, column-level GRANT SELECT in `20261028120000`); a new `worksheets` column needs its own `GRANT SELECT (col) ON public.worksheets TO anon, authenticated` plus an entry in `OWNER_VIEW_COLUMNS` (`src/lib/worksheet/worksheetColumns.ts`, compared with the migration grant list by `worksheetColumns.test.ts`), and client code never uses `select('*')` or a bare `.select()` on it — because an ungranted column fails every owner query with 42501 and the system prompt is core IP.
