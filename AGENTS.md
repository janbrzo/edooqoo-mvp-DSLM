# AGENTS.md — Technical Rules

- AI comparison SEO pages are consolidated into five canonical targets (`/edooqoo-vs-chatgpt.html`, `/chatgpt-alternative-for-english-tutors.html`, `/ai-tools-for-private-english-tutors.html`, `/edooqoo-vs-twee.html`, `/edooqoo-vs-busyteacher.html`); never re-add thin per-tool variants, retire near-duplicates via `CONTENT_OVERRIDES` merge redirects — because 63 near-duplicate pages (containment 0.65-0.93) cannibalized each other in search.
- Thin per-profession static SEO pages (`*-lesson-prep.html`, `*-what-to-teach-next.html`, `*-worksheet.html`) and templated blog articles with boilerplate containment >= 0.80 are retired (301 to `/what-to-teach-next/:slug` or the adult lesson-prep hub) or `noindex,follow` via `templatedCloneNoindexSlugs`; never re-add them to generators, and never link non-indexable routes from related-link meshes or priority hubs — because they carried a rendered `<p>undefined</p>` bug, cannibalized the interactive scenarios, and burned crawl budget (sitemap 407 -> 252 URLs); strategic blog articles (`STRATEGIC_BLOG_SLUGS`, citation or 301 targets) that measure containment >= 0.80 are fixed with page-specific source material in `scripts/seo/strategic-boilerplate-rewrites.mjs` (gated by `seo:audit-uniqueness-gate` in `content:audit`), never noindex or hand-edited HTML, because they carry search intent and link equity that deindexing would throw away.
- Every indexable root `public/*.html` page gets its adult practice task, error table and tool/decision/Gallery links only from `scripts/seo/enrich-pseo-pages.mjs` (packs in `scripts/seo/data/pseo-enrichment-data.mjs`, marker-bounded, run after `seo:generate-ai` and checked in `content:audit`); a new root sitemap page must get a pack mapping, because generators rewrite these files and hand edits or unmapped pages silently lose the enrichment.
- SPA pSEO pages get their differentiating substance from constants, not ad-hoc JSX: `TopicLevelPage` renders per-CEFR guidance from `src/constants/pseoLevelGuidance.ts`, `ExerciseTopicPage` renders per-type mechanics from `src/constants/pseoExerciseMechanics.ts`, and comparison pages carry per-entity `entityProfile`/`criteriaNotes`/`entityFaq` in `scripts/seo/generate-citable-pages.mjs`; `audit-content-uniqueness.mjs` skips pages whose canonical points at another route (canonicalized aliases like `/glossary.html` are consolidated by design) — because two levels of one topic, two exercise types on one topic, and two comparison pages measured containment 0.84-0.90 and cannibalized each other until each got real page-specific content.

One rule per entry, with a one-line why. Replace an existing rule instead of adding a second one on the same topic. Product/UX decisions live in project memory (`mem://`) and `docs/ux/*-spec.md`, not here.

Subdirectories `src/` and `supabase/` have their own `AGENTS.md`; read them before changing files there.

## Protected Systems

- The Worksheet Generation Engine (prompt wording, parameters, pipeline in `supabase/functions/generateWorksheet` and `format-worksheet-prompt`) is never modified without the literal instruction "update the Worksheet Generation Engine" — because it is the core product IP.

## Writing Style

- No em dashes (U+2014, `&mdash;`) in English user-facing, generated or SEO text; use a comma, colon, parentheses, period or a pipe in titles, and use `\u2014` escapes in regexes (enforced by `src/lib/__tests__/noEmDash.test.ts`) — because they read as AI-generated English. En dashes in numeric ranges (`1–6`) stay.

## Documentation & AI Resources

- Public HTML generators must not render bot-directed citation instructions or keyword sections; keep valid JSON-LD keywords/audiences, factual citation paragraphs and dedicated AI resources, because human-facing pages and machine-readable discovery have separate contracts.

- Additional strategic article links are allocated by `scripts/seo/strategic-link-rotation.mjs` to registry-indexable, topic-matched destinations, with at most three new distinct targets per donor; preserve existing recommendations and the graph audit's 10/5 thresholds, because replacing a narrow rotation can silently orphan previously covered pages.

- DSLM preserves `skill_category -> micro_skill -> skill_name` as its three-tier hierarchy; `extract_micro_skill` extensions keep existing real-topic mappings stable and only backfill fallback topics, and read-side pooling happens only in `groupSkillMetrics` through grammar `micro_skill` and the reviewed HIGH/MED cluster table `_shared/skillClusters.ts` (generated by `scripts/dslm/build-skill-clusters.mjs` from `scripts/dslm/data/skill-clusters.csv`, never across categories, LOW task-type families never pooled), with stored `skill_name`s untouched, because renaming atomic evidence or moving established topics fragments learner history.

- `get_student_dslm_state_vector` is an owner/service-only, read-only projection of canonical metrics; its SQL decay helper is parity-tested against `forgetting.ts`, excludes duplicate card metrics and never replaces saved scores or automatically feeds the worksheet engine, because a portable state read must preserve evidence authority and the protected generation contract.

- Recommendation evidence is derived only by the pure `explainRecommendation` helper from targeted skill metrics and explicitly linked source records, with caller-supplied time and shared read-time forgetting; never infer provenance from rationale text or generation counts, reorder lessons or persist derived mastery, because supporting evidence is not proof of an AI model's internal reasoning.
- The competency radar (`src/lib/dslm/competencyRadar.ts` + `CompetencyRadarView`) classifies categories into critical_gap/retention_alert/mastered/in_progress from caller-supplied raw and effective mastery and never applies decay itself; its "Add to next lesson" action only writes the manual prefill sessionStorage keys and navigates, because evidence UI must stay read-only and must never arm auto-generation or touch the Worksheet Generation Engine.

- Teacher lesson evidence panels share `WhyThisLessonBanner` and the cached `usePlanEvidenceMetrics` read; worksheet passports are revalidated against the exact active suggestion, learner/teacher scope and applied text, because carousel position, edits and student switching must never expose another lesson's or learner's evidence.

- Every sitemap URL is served `index,follow` with a self canonical to the clean URL (asserted by `scripts/seo/audit-seo-assets.mjs` and `audit-sitemap-integrity`); a page is de-indexed only through `noindex` in `scripts/seo/content-registry.mjs`, which also drops it from the sitemap and requires removing internal links — because sitemap+noindex conflicts triggered GSC indexing alerts.
- `public/llms.txt` and root `llms.txt` are generated only by `scripts/seo/generate-ai-resources.mjs` and gated by `scripts/seo/audit-seo-assets.mjs`; never hand-edit them or append release notes, and change wording in the generator, not the output; generators stay deterministic (fixed `RELEASE_DATE`/`VERSION`, no `new Date()`), and CI invokes the same `seo:sync-generated` command as local synchronization twice with a clean-diff check after each run, then `content:audit` and check-only snapshot/backlink guards before the production build, because duplicated generation sequences drift and a single clean run does not prove repeatability.
- `docs/llm-context.md` is updated only for architectural changes (new module, table, Edge Function, route contract) in the `PROBLEM -> EDOOQOO SOLUTION -> TECHNICAL MECHANICS -> RAG KEYWORDS` format — because per-fix changelog entries bloat agent context and go stale.
